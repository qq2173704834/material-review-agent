# 本地身份与任务授权（N01）

默认启动仍是本机单用户模式，服务绑定 127.0.0.1。需要不同用户身份时，在忽略的 `.env.local` 增加 `REVIEW_ACCESS_USERS` JSON 数组，每项包含唯一 `id` 和独立随机 `token`（32–256 字符）。可用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 在本地生成凭据；不要发送到聊天、记录到 Git 或复用模型 API 密钥。

配置示意（替换占位符，勿直接使用）：

```dotenv
REVIEW_ACCESS_USERS='[{"id":"owner","token":"替换为独立随机32字节十六进制凭据"},{"id":"reviewer","token":"替换为另一份独立随机32字节十六进制凭据"}]'
```

重启后到 `/access` 登录，凭据保存在 HttpOnly、SameSite=Strict、8小时有效的 Cookie 中；HTTPS 使用 Secure。脚本调用可使用 `Authorization: Bearer <token>`。不记录凭据，不返回配置值。撤换配置中的 token 并重启会使该身份旧登录立即失效。所有者 ID 更名不迁移任务所有权。

首次从单机模式迁移时，配置中第一位身份接管旧任务。先确认第一项身份正确并备份本地数据库。新建任务和演示副本归当前登录身份；列表与首页仅显示自己的和获授权的任务。任务所有者在“任务访问授权”中授予或撤销其他已配置身份的本任务读写权限；被授权者可查看、编辑、审查、导出，但不能转授授权。撤销仅阻止后续请求，已经下载的副本不能撤回。

当前实现面向本机/受控环境身份隔离，采用管理员分配的访问凭据，没有邮件注册、密码找回或外部 OAuth。不要将未启用身份的单机服务直接暴露到公网。身份凭据只用于本地应用，不作为上传材料的一部分。

自动验收：`pnpm exec playwright test --config=playwright.access.config.ts`，使用隔离数据库和固定合成凭据，验证匿名拒绝、跨身份任务/报告入口、首页隔离、授权/撤销、URL 编码绕过、跨站写入与浏览器登录/退出。
