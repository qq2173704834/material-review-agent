# 学校名称查找与官网选填

日期：2026-11-15，ENG-097 / BUG-057。

用户截图中的“提交接入建议”原指：提交尚未收录的学校名称与官网，由维护人员核对后补充公开通知来源。该表单被误当作学校查找入口，而且前端required和接口校验均要求官网，阻碍只知道学校名称的用户。

本次调整：

- 名称输入支持已有学校的片段匹配，例如“第二工业大学”可以找到“上海第二工业大学”，点击选择后保存学校并展示本校通知，不提交添加申请。
- 未收录学校使用“申请添加学校”，学校名称必填、官网选填。明确申请由维护人员后续处理，不宣称提交后已经接入，也不自动搜索或抓取用户填写的网站。
- 接口支持省略官网和空字符串；填了官网时继续校验完整HTTPS地址。失败保留输入，提交按钮显示处理中。
- 后台显示“学校添加申请”，未填官网时显示“未提供官网”，不生成空链接。
- 重复申请按当前用户、标准化学校名称或相同非空官网去重；可给已有的名称申请补充官网，达到10条时重复操作仍可成功。

原申请表以用户/网址为主键，不能表达同一用户提交多所未填官网的学校。新增`campus_school_requests_v2`，以独立申请键保存，官网保留真实值或空字符串；旧表不删除，按原用户、网址、名称和时间幂等导入新表，保留旧记录，避免伪造网址作为主键。管理员列表改读兼容后的表。

新增隔离回归覆盖名称选择不产生申请、仅名称提交、多个无官网学校、重复及补充官网、配额、格式与登录/管理员门禁、旧申请两次读取不重复。所有写入均在测试专用目录，未操作现用用户数据。

验证：学校申请3项、校园与信息结构既有11项，共14/14通过；生产构建、TypeScript、ESLint、本轮Prettier及差异检查通过。没有新增需要独立单元覆盖的计算逻辑，接口与真实保存通过集成用例核对。三个原配置文件SHA256保持，排除本轮提交；不推送部署或关机。
