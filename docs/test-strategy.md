## 模式区分

| 模式         | 使用范围                                         | 能证明什么                                            | 不能证明什么                                           |
| ------------ | ------------------------------------------------ | ----------------------------------------------------- | ------------------------------------------------------ |
| 模拟模式     | 固定 AI/外部服务响应，正常/超时/失败/错误结构    | 已覆盖的 UI、工作流、错误处理、工具调度及状态变化     | 真实模型提取质量、真实外部可访问性或被 mock 的解析能力 |
| 工具集成验证 | 合成 PDF 经真实解析和确定性检查工具              | 被测 PDF 类型、字节数、页数、覆盖与错误分支的实际行为 | 没有调用的模型、OCR 或语义检索效果                     |
| 免费真实联调 | 服务商确定后实际调用免费 API 和真实解析/检索链路 | 特定模型、样本、时间和配置下的事实、结构、证据结果    | 全面准确率、稳定商用保障或未测格式能力                 |

免费是计费条件，不是模拟标志。每次报告记录模式、环境、模型/提供商（如适用）、样本、时间、已执行/未执行/跳过数量、耗时及可测成本；不要求自然语言逐字一致。

## 合成样本与断言方向

准备两类领域通知，人工标注材料对象、强度、适用条件、数值边界、原文位置及预期结论；包含正常与缺失材料、恰好等于上限、超过上限、正文/总页数差异、空/损坏/加密/扫描 PDF、标题无正文、干扰指令、修订版。样例不能写死模型输出或预设为所有通知的规则。

真实模型断言关注独立规则事实、参数和单位、引用是否实际存在、条件未知是否待确认、五类判定合法性及证据是否支持结论。规则遗漏与误报单独计数，说明样本数量与评估条件，不虚构准确率。

## 隔离、维护与功能退出条件

- 只使用合成数据、独立测试 SQLite 目录和测试专属任务；准备/清理检查测试标记和归属，只清理由本次测试生成的数据。
- 固定样例与用例入 Git；临时上传、报告、截图、浏览器轨迹和凭据默认忽略；日志不保留密钥和完整敏感材料。
- 每个功能执行必要静态检查和有意义场景，审查差异，再使用实际验证结果提交；关键 bug 增加复现回归，低影响样式调整不堆砌重复测试。
- 页面测试通过、工具集成通过、真实语义通过分别记录。未配置真实 API 时明确“未执行”，不能默认为跳过即通过。
- 初始化阶段验收包含实际启动、构建、类型检查、lint/格式检查及测试入口；执行结果在任务与初始化记录中逐项写明，不与业务验收混淆。
