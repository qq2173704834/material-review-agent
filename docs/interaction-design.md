# 三阶段交互设计与实施说明

日期：2026-11-13。任务：ENG-022（U0 原型）、ENG-023（U1—U3 实现与工程复验）。用户已授权开始实现 UX-01—UX-09；独立人工体验验收不伪造。

## U0 原型

[可切换的关键页面原型](prototypes/interaction.html) 包括准备、审查、结果三张页面，支持正常、读取失败/中断、修订待复检分支；移动布局切换为单列。原型是设计示意，不调用模型，示意计数不是实际结果。

已用 Chromium 核对三视图切换、1440×900/390×844 布局和失败/待复检分支，六张截图存于忽略的 test-results/ux-prototype/；并实际查看移动准备页截图。设计自查后按以下结构实施；不把设计自查称为用户验收：

- 准备：来源和待审材料分区，选择后自动上传；任务背景折叠，审查要求可展开纠正。
- 审查：任务头部的唯一主动作串联保存、要求准备和检查。集中澄清与部分读取先说明影响，再由用户补充或明确跳过/继续。
- 结果：默认需处理问题；问题处打开材料、条件或审查要求面板，关闭后保留问题和筛选。完整五类判定、未执行、有效性及版本继续区分。
- 手机首屏保留主按钮，导航三等分；面板独立滚动，按钮不盖住正文。

## 实施约束

TaskWorkspace 管理阶段、主操作、可访问处理面板和准备活动。阶段切换仅隐藏非当前内容，保留已挂载编辑器与上传队列；不会自动触发模型调用。选中执行、问题和筛选继续通过非敏感 URL 参数恢复。

实际检查复用现有检查流与快照；开始前读取已保存的最新任务和规则，已有有效人工要求直接复用。来源变化且包含人工调整时停止自动覆盖，提示用户核对并明确重新整理。上传中与编辑未提交时不启动重复审查。

已有服务端执行互斥继续保留，并为要求整理增加互斥和准备复用。文件上传使用可恢复队列；同内容重传不生成无意义版本，同名不同来源内容进入显式修订。现有本地数据库和环境配置不迁移、不重置。
