# 开发计划与最小审查闭环

更新：2026-11-13（Asia/Shanghai）。本轮补齐及验收结果见 acceptance-2026-11-13.md，原始范围状态见 requirements-status.md。下方阶段表保留原开发顺序和退出条件，不以旧的“待实现”文字覆盖最新记录。

## 范围与完成定义

2026-11-12 形成优化需求；2026-11-13 已按用户授权推进实现和验收。后续优化按 [产品优化需求](optimization-requirements.md) 第 5 节安排为 B1 基础体验、B2 处理与复检、B3 评估与交付；B1 优先完成工作台、导航、材料匹配、原文证据及覆盖展示，B2 先统一修订与失效记录再做增量复检，B3 完成样例评估和 PDF 报告。既有未完成需求继续保留，新文档不表示功能已完成，也不承诺比赛日期或模型效果。

用户同意先做临时名「材料预审工作台」的单机本地版，先用免费模型接口测试、暂不部署。最小可交付目标：

1. 创建任务，保存本次文本通知与任务背景，刷新后可恢复。
2. 从当前通知提取材料清单和独立规则，保留原文位置、强度、条件与参数；只就影响判定的歧义集中询问。
3. 首批支持常见材料格式：PDF、DOCX、TXT、XLSX、CSV、JPG、PNG；按格式解析文本、段落/表格、图片 OCR 和适用的页数/工作表属性，显示解析范围、失败原因和匹配不确定性，允许人工纠正匹配。当前 JPG/PNG 和扫描/混合 PDF 用本地中英 OCR，记录逐页范围；复杂表格结构和手写质量仍未保证。影音、压缩包和专业格式后续评估。
4. 对适用的要求执行完整性与规格检查，展示逐项真实进度、五类判定、原因、原文和材料证据。
5. 替换材料或修订文字后使受影响旧结果待复检，依据依赖默认增量执行，可选全量，复用保留原执行与时间。
6. 导出同快照 Markdown 与打印 HTML/PDF，含时间、来源、版本、结论、建议与未核验内容。

这是有边界的首批方向。每项完整需求的具体覆盖随任务记录维护；格式能力需逐个实测，不能因为一个格式可解析就把 M03 全部标为完成。免费接口未提供时，可先完成模拟工作流与真实确定性工具，但不能把最小 AI 闭环标为真实验收完成。

## 最小业务数据设计方向

以下只是概念边界，不是数据库迁移或已定 API：

- 任务包含独立 ID、名称、背景和更新时间；来源保存原文、位置、解析状态与版本。
- 规则包含编号、描述、目标、强度、条件、参数/边界/单位、来源证据、能力类型、生成方式、版本与人工修改标记。
- 材料与材料版本保存真实类型、字节数、总页数、解析状态和覆盖、文件安全引用；匹配关系独立保存且可人工修正。
- 执行快照记录来源/规则/材料/匹配版本、模式与模型、检查计划、工具事件及终止原因；结果保存判定和独立执行状态。
- 证据保存实际段落或页码及上下文；整改记录保留人工动作；结果有效性描述是否受当前版本变化影响。

## 边界与失败处理

- 自动判定限于有来源依据且具备对应工具或证据的约束。模型抽错参数、条件未知、来源冲突须暴露，不能用默认值偷偷决定。
- PDF 总页数检查只对应“总页数”约束；正文范围不能确定时待确认。扫描件、低质量解析和能力未支持分别说明原因。
- 来源和材料均为不可信数据；工具只能用受限业务参数。模型不得直接调用任意命令、任意 URL 或文件路径。
- 服务器验证输入和模型输出，限制上传、重试和调用数量。不同单项可独立失败，失败信息不得泄漏密钥或整份敏感原文。
- 浏览器中展示真实步骤和已完成计数，不编造思考过程、固定准确率或假进度。没有发现明确问题与全部适用项验证通过分开表达。
- 本地单人版不公开访问；需要多人/公网时，先实现任务归属与授权、存储隔离、删除覆盖等再发布。
