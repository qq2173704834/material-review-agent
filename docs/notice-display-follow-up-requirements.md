## UXR-34 上传后材料区精简

优先级P1。用户反馈上传文件后显示过多详细信息，导致页面复杂：[原始反馈截图](assets/feedback/material-upload-details.png)。静态定位src/components/material-upload.tsx和material-revision.tsx中的读取/版本、解析修订、逐页范围和定位片段入口；本条属于展示精简，不据截图声称上传或解析故障。

| 条件      | 具体需求与验收标准                                                                                                                                                                                                                                                                         | 状态   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| UXR-34.A1 | 已上传材料采用紧凑文件行/卡片，默认只突出文件名、处理中/可检查/需处理等用户能理解的状态和必要操作。版本号、大小、页数等元信息不再成排占据主视图；确有约束问题时再就近说明。文件选择、替换、删除及开始检查等入口保持清楚，避免每份文件占据大段页面。                                        | 待实施 |
| UXR-34.A2 | 从普通用户上传后主界面移除“读取与版本详细信息”“核对与修订解析文字”“逐页读取范围”“查看N个定位片段”等成排技术入口，不仅将它们再放进另一个默认可见的复杂区域。查看文件使用单个清楚入口；解析修订只在确需纠正时按需出现，证据定位在具体检查问题/结果中使用，技术诊断留在维护侧。               | 待实施 |
| UXR-34.A3 | “材料类型待确认，可展开文字核对后纠正”等实现说明改为可执行的简短提示，例如“请选择材料类型”配直接选择。读取失败、部分读取或文件确需用户处理时，显示简短原因与重试/重新上传/按需核对操作，不将失败显示为成功或静默掩盖未读取范围；具体影响在相关结果中说明。后台原件、快照、解析和证据保留。 | 待实施 |
| UXR-34.A4 | 后续覆盖单文件/多文件、长中文文件名、处理中、读取完成、失败重试、部分读取、材料类型确认与手机布局；确认能快速找到文件和下一步。对照原件/检查结果验证精简展示后依然可核对必要证据，不改变服务端判定。完成实现及回归后才更新状态，本轮仅登记。                                               | 待实施 |

本条不自动扩展为删除链接/公开仓库材料功能；用户本次针对上传后详细信息展示，不据截图删除其他业务能力。

## UXR-35 将字段对齐改为可理解的材料信息核对

优先级P1。用户反馈“跨材料字段对齐”让用户不明所以，希望优化：[原始反馈截图](assets/feedback/material-field-alignment.png)。现有FieldMappings组件是原文字段/主体对应关系的人工确认入口，不是仅靠改名就能自动完成的检查；后续展示需区分“确认对应关系”和“运行一致性检查”。本轮不据截图登记字段判断错误。

| 条件      | 具体需求与验收标准                                                                                                                                                                                                                                                                                                | 状态   |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| UXR-35.A1 | 普通用户以“材料信息核对”等业务名称理解此功能；配一句简短用途，例如“帮助核对不同材料中的姓名、证件号码等信息是否一致”，举例限定为实际支持/识别到的项目。人工确认入口明确叫“确认信息对应关系”，不把尚未执行的检查显示为已检查。主界面移除字段对齐、标准字段、映射等实现术语。                                       | 待实施 |
| UXR-35.A2 | 默认用简洁状态和必要操作承接流程；仅一份材料、没有可比信息或当前无需确认时，不展示整块复杂配置表单。确需用户确认时给出真实待确认项和“去确认”操作；没有执行检查时不显示“全部一致”，未支持/未提取不当作通过。                                                                                                       | 待实施 |
| UXR-35.A3 | 需要确认时用对照卡片/表格展示文件名、信息名称、原文值和必要位置。例如“报名表：姓名 张三；证明：申请人 张三”，让用户确认是否同一人、是否同一项信息，提供确认/不是同一项/暂不确定等清楚动作。姓名相同不自动合并不同角色，原始值保留，证件号按权限与必要范围展示。避免默认要求用户手填主体、标准字段和技术映射说明。 | 待实施 |
| UXR-35.A4 | 后续验证同义字段、相同姓名但不同角色、值不一致、缺失/遮挡、无候选/单材料、暂不确定、保存失败、材料替换及手机对照布局。确认记录与实际文件/位置绑定，换材料后重新核对，不能通过简化界面跳过权限或证据校验；最终检查仍由原有受控流程执行，不靠用户确认直接判通过。                                                   | 待实施 |

同时将截图中来源摘要的“公告v1”纳入UXR-33.A1，属于原需求补充，不重复增加版本清理条数。保留可追溯原文与底层快照，无需用户理解内部版本。
