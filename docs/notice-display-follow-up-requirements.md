优先级P1。用户反馈上传文件后显示过多详细信息，导致页面复杂：[原始反馈截图](assets/feedback/material-upload-details.png)。静态定位src/components/material-upload.tsx和material-revision.tsx中的读取/版本、解析修订、逐页范围和定位片段入口；本条属于展示精简，不据截图声称上传或解析故障。

| 条件      | 具体需求与验收标准                                                                                                                                                                                                                                                                         | 状态   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| UXR-34.A1 | 已上传材料采用紧凑文件行/卡片，默认只突出文件名、处理中/可检查/需处理等用户能理解的状态和必要操作。版本号、大小、页数等元信息不再成排占据主视图；确有约束问题时再就近说明。文件选择、替换、删除及开始检查等入口保持清楚，避免每份文件占据大段页面。                                        | 待实施 |
| UXR-34.A2 | 从普通用户上传后主界面移除“读取与版本详细信息”“核对与修订解析文字”“逐页读取范围”“查看N个定位片段”等成排技术入口，不仅将它们再放进另一个默认可见的复杂区域。查看文件使用单个清楚入口；解析修订只在确需纠正时按需出现，证据定位在具体检查问题/结果中使用，技术诊断留在维护侧。               | 待实施 |
| UXR-34.A3 | “材料类型待确认，可展开文字核对后纠正”等实现说明改为可执行的简短提示，例如“请选择材料类型”配直接选择。读取失败、部分读取或文件确需用户处理时，显示简短原因与重试/重新上传/按需核对操作，不将失败显示为成功或静默掩盖未读取范围；具体影响在相关结果中说明。后台原件、快照、解析和证据保留。 | 待实施 |

本条不自动扩展为删除链接/公开仓库材料功能；用户本次针对上传后详细信息展示，不据截图删除其他业务能力。

## UXR-35 跨材料信息核对融入统一审查

优先级P1。用户已进一步澄清：不是把“跨材料字段对齐”改名继续展示，而是取消单独的用户模块，将能力结合在审查中。本节取代ENG-087最初“独立信息核对/按需配置”的方案，不新增编号或条数。[原始反馈截图](assets/feedback/material-field-alignment.png)。

| 条件      | 具体需求与验收标准                                                                                                                                                                                                                                                                              | 状态   |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| UXR-35.A1 | 普通用户任务页面移除独立“跨材料字段对齐”模块及主体、标准字段、映射等配置入口，不另换名称保留同一块前置表单。用户上传材料后直接进入统一审查，无需先完成字段对齐才能开始。                                                                                                                        | 待实施 |
| UXR-35.A2 | 将适用的跨材料信息一致性核对纳入“开始审查”的检查计划，与完整性、格式等检查一并运行并返回结果。系统在支持范围内识别同一主体及同类信息，不要求用户逐条配置；依据不足时记为待确认/无法检查，不自动合并不同人物、角色，不阻塞无关检查。单材料或没有适用比较项时不展示多余配置，也不虚构“一致”结论。 | 待实施 |
| UXR-35.A3 | 结果中用“姓名不一致”“证件号码需要确认”等直接业务表述问题，按需展示涉及文件、原文值、位置和处理建议，避免输出字段映射过程。正常项沿用简洁通过汇总；只有无法可靠识别关系且影响结论时，才在对应结果项内请求最小必要确认，允许暂不确定，不重新出现独立配置模块。                                    | 待实施 |
| UXR-35.A4 | 后续验证“上传多份材料→直接开始审查→发现差异→按结果定位/必要确认→复检”完整链路，覆盖一致、同义字段、不一致、不同角色、缺失/遮挡、单材料、材料替换、失败重试与账号隔离。确认按原件和快照保存，替换后相关结果待复检；隐藏模块不删除后台证据，人工确认不直接覆盖原始判定。                          | 待实施 |

现有FieldMappings人工入口需在后续实现时融入统一审查结果处理，而不是仅做文案替换；本轮只记录目标行为，尚未改动检查流程。同时将截图中来源摘要的“公告v1”纳入UXR-33.A1，不重复增加版本清理条数。
