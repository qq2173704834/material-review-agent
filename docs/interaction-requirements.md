# 材料预审工作台 · 交互改造需求

版本：1.0。日期：2026-11-13（Asia/Shanghai）。依据：用户实际试用反馈“主体功能还可以，但是交互方式太反人类”，并要求将本轮公开项目调研建议转为具体需求。

本文件形成下一轮交互改造的需求基线。本轮仅编写需求与计划，未实施应用改造。原始 114 条功能编号和 OPT-01—OPT-10 保留；UX-01—UX-09 是与它们关联的体验细化，不能重复相加为功能总数。共 9 个需求组、36 个验收条件，全部待开发/待重新验收。

## 1. 目标与完成定义

用户提供审查要求和材料后，能够自行开始审查、理解问题、核对证据、处理问题并导出结果。主要流程不要求用户先学习规则集、解析器、执行快照等工程概念。

主流程统一为：**准备要求与材料 → 执行审查 → 处理问题与导出**。这三个视图承担导航；澄清、规则编辑、历史和诊断按当前任务需要展开。

五类判定、硬性问题与建议分区、真实证据及位置、版本留痕、增量/全量复检、任务授权和真实/模拟模式继续按既有规则执行。界面简化不能隐藏未核验范围、把手工处理当作系统通过，或把历史结果冒充当前结果。

同届项目提供设计参考，具体依据见 [调研记录](research/chuanzhi-9-project-review-2026-11-13.md)。本轮不增加新领域业务、3D场景或账户平台；采用现有技术方向和检查能力。

## 3. 核心主操作与状态约定

以下为 UX-01/04 共同使用的状态说明，不额外计为编号需求。先判断当前数据和执行是否有效，再确定主操作；界面刷新或重渲染本身不触发外部模型请求。

| 当前任务情况                                   | 主要操作或状态   | 用户点击后发生什么                                                    |
| ---------------------------------------------- | ---------------- | --------------------------------------------------------------------- |
| 没有可用的审查要求                             | 添加审查要求     | 进入准备视图并聚焦要求入口                                            |
| 文件正在上传或解析                             | 正在准备材料     | 显示实际逐文件状态；提供取消或失败处理入口，防止重复启动              |
| 全部要求来源读取失败                           | 处理要求读取问题 | 展示具体失败和粘贴/重传入口                                           |
| 有可用要求和待审材料、处理已结束、尚无检查结果 | 开始审查         | 保存有效输入，按需整理规则并执行审查                                  |
| 有可用要求但没有待审材料                       | 检查缺交项       | 解释此次可检查缺交情况，内容检查可能待确认/无法检查；另有添加材料入口 |
| 正在整理规则或检查                             | 正在审查         | 展示真实阶段和取消入口；不创建第二次执行                              |
| 执行中断或失败                                 | 重试审查         | 显示失败范围；复用已保存的准备成果，在现有限额内重试                  |
| 当前结果因变更已失效                           | 复查受影响项     | 展示影响摘要，默认增量；全量复检为可选操作                            |
| 当前结果有效，存在需处理或未核验项             | 查看待处理问题   | 打开结果视图和对应问题筛选                                            |
| 当前结果有效，无需处理项                       | 查看报告         | 展示五类判定和检查范围后进入报告操作                                  |

有关键条件未决时，开始入口仍可使用，集中展示待补充事项并允许跳过；只让相关项保留不确定。部分材料失败时说明影响，允许用户明确选择基于可用材料继续；失败材料不会被当作完整已读。

真实模式缺少必要模型配置时展示配置入口并保留输入。用户可明确选择模拟演示，入口和结果持续标明模拟；禁止静默切换。外部模型将读取哪些通知/材料范围的说明放在启动区域，密钥不在任务页展示。

## 4. 逐项需求与验收条件

### UX-01 随任务状态变化的唯一主操作

目标：用户在任务打开后的当前屏幕能立即知道下一步做什么。

- **UX-01.A1**：任务头部根据第3节状态表提供一个视觉上占主导的业务操作。1440×900、1280×800 的首屏可见；390×844 下置于可见或固定操作区，无遮挡内容、无整体横向溢出。
- **UX-01.A2**：主要操作旁说明前置条件或缺口。禁用时给出具体原因与补救动作；无材料时保留“检查缺交项”，不因未上传而统一禁止审查。
- **UX-01.A3**：开始动作发出后立即显示真实准备/执行状态并防重复点击；上传、整理规则、检查中均不能因连点创建重复执行。取消保留已保存输入和已完成结果，清楚标记未执行部分。
- **UX-01.A4**：任务列表和详情对同一任务给出一致的继续入口。返回已有任务后依其当前状态显示继续准备、查看结果或复查；查看历史记录时清楚区分历史与当前操作对象。

### UX-02 三阶段视图与任务状态恢复

目标：按当前工作组织页面，用户无需在长页内寻找下一处操作。

- **UX-02.A1**：准备、审查、结果为可切换的独立内容视图。切换会显示相应主要内容，不能只滚到同一长页的锚点；主任务标题、当前状态和主操作保持可辨认。
- **UX-02.A2**：准备视图集中来源和材料；审查视图集中执行与局部结果；结果视图集中问题、证据、整改和导出。背景、完整规则编辑、历史和诊断使用标签/抽屉/面板按需打开，保留原有能力入口。
- **UX-02.A3**：同任务切换视图保存未提交的编辑草稿、材料选择和已选问题；刷新/后退恢复已保存视图、执行记录、问题和筛选。未保存输入遇刷新或离开给出提醒，目标失效时解释并回到有效位置；URL不写入材料原文或敏感字段。
- **UX-02.A4**：执行结束后仍在审查视图的用户自动进入本次结果并收到可访问的完成提示；用户主动转去编辑或查看其他问题时，不自动抢走当前内容。历史入口总能读取该次来源、规则与材料版本，不能混入当前版本。

### UX-03 要求与材料分区、自动上传和失败恢复

目标：用户能分清用什么要求审查、哪些文件是被审查对象，并看到每份文件真实状态。

- **UX-03.A1**：准备视图有“审查依据”和“待审查材料”两个明确区域，分别说明通知/指南/模板与申请书/证明/项目文件的用途，支持既有输入方式。相同PDF等格式由用户选择的区域决定用途，不能按扩展名猜测。
- **UX-03.A2**：选择或拖入文件后自动加入对应上传解析队列，逐文件显示等待、上传、解析、成功、部分成功或失败；无需另找“上传N个”按钮。既有大小/数量/格式和解包限制保留，失败原因在该文件旁可见。
- **UX-03.A3**：失败文件可就地重试、重新选择或移出本次准备；已成功文件和填写的要求不被清空。相同内容重复添加不产生无意义版本；同名不同内容进入可理解的修订流程，不静默丢失原件与旧版本。
- **UX-03.A4**：准备区展示可用要求来源数、材料数和待处理文件数，以及内容分类/匹配不确定提示。可预览解析范围和纠正匹配；有失败/部分读取时明确继续审查的影响，不能显示为全部准备成功。

### UX-04 一次操作串联准备规则与审查

目标：普通用户点击开始后，由系统串联内部步骤，完整规则仍可查看、纠正和追溯。

- **UX-04.A1**：要求和材料就绪后，点击一次“开始审查”即完成必要保存、规则准备和检查，不强制用户先单独找到“生成规则草稿”。缺失/过期规则按需整理，已有有效规则直接复用；已保存的人工纠正不得被静默覆盖。
- **UX-04.A2**：“查看/调整审查要求”始终可访问，展示引用和要求强度。来源变化后展示更新及人工改动冲突的摘要，需选择时集中处理；新的来源/规则版本只影响后续检查，不改写旧执行结果。
- **UX-04.A3**：统一显示实际的读取材料、整理要求、检查、汇总阶段及逐项结果；已完成阶段不假装重跑。量未知时不显示虚构百分比；局部失败允许独立项继续，重试和取消遵守原有限额并保留真实状态。
- **UX-04.A4**：已知的未决背景和冲突在正式检查前一次汇总，可回答或跳过；跳过不阻塞独立项。正式执行检查前固定本次使用的数据版本及澄清回答；执行期间上传/编辑的新版本标为待下次检查。刷新仅恢复已保存进度，实际中断明确提示，不伪装后台仍在运行，也不自动重新收费调用。

### UX-05 结果优先、证据联动的问题工作台

目标：先回答有什么需要处理，再让用户逐项核对依据。

- **UX-05.A1**：结果首屏展示本次完成/取消/中断状态、五类判定数量、未执行和待复检提示。“需处理”按必须项未通过、待确认、无法检查及未执行分别统计，明确分母和统计范围；可选建议不混为硬性违规。
- **UX-05.A2**：默认打开需处理列表，排序为必须项明确未通过、待确认、无法检查/未执行；提供查看全部与清除筛选。没有明确问题但存在未核验项时说明缺口，不能使用“全部通过”；只有满足既有报告条件时才显示相应通过表述。
- **UX-05.A3**：问题卡默认展示问题、影响材料、要求/判定和可执行建议，选择后在同工作空间打开相应来源和材料证据。对照问题可看双方版本与位置；缺证据、旧原件不可用或部分解析明确回退，不伪造定位。
- **UX-05.A4**：从问题到证据、整改再返回时保留当前问题、筛选和列表位置；复检后显示已解决、新增、仍存在及不确定项。完整报告、整改清单和副本包在结果视图有清晰入口，导出沿用选定执行/材料版本，失败可重试。

### UX-06 在问题处完成澄清、整改和复检

目标：用户发现问题后，在问题附近完成处理并理解处理后的结果有效性。

- **UX-06.A1**：按问题原因提供对应动作：缺材料→上传；条件未知→补充背景；匹配不确定→更换材料；来源冲突→查看双方并选择依据；解析问题→重试/文字纠正；异议→人工复核。动作在问题卡或其关联面板中可达，不要求回长页寻找全局表单。
- **UX-06.A2**：相同条件合并成一次补充，允许跳过；面板可同时看相关要求原文。提交失败保留输入，关闭和返回保留上下文，成功后显示影响的规则及待复检状态；未知信息不自动补为满足。
- **UX-06.A3**：从问题上传修订版、分派/认领待办或记录处理状态均保留任务、材料和执行归属。手工标“已处理”与系统结论分开展示；人工认为符合必须记录依据，不能直接改写原判定或把问题计为已解决。
- **UX-06.A4**：修订后问题旁和任务主操作明确提示“复查受影响项”，提供影响摘要和全量入口。完成后可回看本次变更和问题变化；无可靠依赖或证据时保守扩大重查，不为了减少步骤而错误复用。

### UX-07 用户文案与详细信息分层

目标：普通视图表达任务目标，专业细节在需要核查时可获得。

- **UX-07.A1**：主要流程统一使用第5节词表；五类判定名称及含义保持一致。“尚未执行”“正在执行”“已完成”和“待复检”明确为执行/有效性状态，不能作为新的判定类别。
- **UX-07.A2**：默认展示任务、材料、问题、覆盖和下一步动作。内部ID、解析器名、哈希、模型用量及完整版本明细收于“详细信息/检查记录”；不能折叠掉当前模式、关键失败、证据缺口或影响判断的限制。
- **UX-07.A3**：错误提示包含发生了什么、哪些内容受影响、现在能做什么，并就地给重试/替代入口。表单错误关联对应字段，保留输入；普通页面不直接展示堆栈、密钥或内部磁盘路径。
- **UX-07.A4**：桌面和移动使用相同核心名称及动作；标签同时有文字，状态不只靠颜色表达。只显示当前确有内容或用途的区块，空区块可提供补充入口，但不展开整套无关设置。

### UX-08 可跳过、可重看的引导和独立示例

目标：首次用户可借助简短引导体验完整流程，熟悉后可以直接工作。

- **UX-08.A1**：首次提供最多3步的引导，覆盖准备、开始、处理结果；可随时跳过，通过固定“怎么用”入口重看，关闭后不阻止任何已授权功能。老用户不反复被强制引导。
- **UX-08.A2**：新手可一键创建独立示例并开始体验；已有任务内容不被覆盖，展示历史示例结果与真实本次运行清楚区分。模型配置不足时明确展示模拟方式及其局限，不冒充真实审查。
- **UX-08.A3**：任务列表显示“继续准备/查看问题/待复检”等可理解状态；返回已有任务直达适合的视图。恢复失败给出原因和有效入口，不创建重复任务，也不把草稿内容无提示丢弃。
- **UX-08.A4**：引导支持键盘、跳过和关闭后的焦点返回，遵循减少动画偏好；弹层不遮挡必要动作。首屏主要按钮和名称自身可理解，不以用户必须看完教程作为开始条件。

### UX-09 易用性、键盘和响应式专项验收

目标：把用户能独立完成任务作为交付条件，避免仅以按钮可点击就标为体验完成。

- **UX-09.A1**：建立第7节六条任务走查及相应自动化回归。必须包含“新建任务后不知道如何开始审查”的复现与改进对照，保留场景版本、预期、实际和问题记录；测试使用独立数据，不改用户真实任务。
- **UX-09.A2**：至少3位未读开发文档的首次使用者走查，验收目标为3位均在30秒内找到下一步主操作，并在不接受口头指路的情况下完成准备→审查→证据→修订复查→导出。记录操作时间、误操作、求助和退出点，后台处理耗时单列；未实际组织前保持待验收，不虚构参与者或结果。
- **UX-09.A3**：在1440×900、1280×800和390×844验证主操作、阶段切换、结果预览、就地整改与导出。无整体横向溢出，固定按钮不盖住内容，主要触控目标至少44×44 CSS像素；长文档预览可独立滚动。
- **UX-09.A4**：主要流程全程可用键盘操作，焦点可见；面板打开后焦点进入、关闭后返回触发点，没有键盘陷阱，状态和错误可被辅助技术感知。普通文字对比度至少4.5:1、大文字至少3:1；自动检查和人工辅助技术检查分别记录，不能相互代替。

## 5. 主要文案词表

以下调整用于主要交互，详细信息中保留准确的技术说明。“审查依据”指通知等来源原文，“审查要求”指从原文整理出的检查项，两个入口不得混淆。

| 当前术语       | 主要界面表达           | 说明                              |
| -------------- | ---------------------- | --------------------------------- |
