# 校园通知与学业日程需求

日期：2026-11-15（Asia/Shanghai）。登记任务ENG-088。用户希望增加学校新通知获取、期中/期末考试和作业截止日期管理，并询问如何设计。沿用本轮只做需求、不写代码要求；登记CAMP-01—06共6组24条，全部待实施。页面组织与批次为设计建议，尚未指定首批学校、接入网站和开发工期，不代表现有功能已支持。

## 产品定位与入口

建议增加“校园事务”入口，含“学校通知”“我的日程”两个子页：学校通知解决新消息发现，个人日程承接期中/期末考试、作业、课程报告与活动节点。首页只放紧凑的本校新通知/近期截止摘要，不把所有校内内容挤进全国考试发现；备考中心复用同一日程数据并提供类型筛选，不另造重复日历。

设置学校为必要信息，学院/专业、年级/班级为可选，用于相关性筛选；初期不要求学号、教务密码或课表授权。首批按实际可接入的公开站点逐校上线，不承诺自动覆盖所有高校。学校信息缺失时可先手动管理日程。

通知范围建议包括教务考试、选课/补退选、四六级校内报名、竞赛、奖学金/评优、讲座/活动、实习就业等。来源主要为公开官网/教务处/学院网站；校内系统、班级群、公众号等内容通过用户粘贴文字、上传通知/截图或手动录入补充，首版不自动登录私人系统或读取聊天记录。

## 展示与核心流程

- 学校通知卡片：标题、发布部门/日期、类别、是否未读，以及有依据时的临近截止提示；保留查看原文与加入日程。采集技术、内部版本与诊断不展示给学生。
- 日程卡片：事项/课程、类型、时间或截止倒计时、地点（有时）、待完成/已完成及提醒。考试用起止时间，作业用截止时间，避免把两者混为同一种日期。
- 导入流程：通知文字/文件/截图/链接 → 识别可支持的日期与事项 → 用户核对一张简洁预览卡 → 保存到个人日程。普通通知没有日期也能被阅读，不强制建日程。
- 示例：学生粘贴“数据结构实验报告下周五晚八点前交”，系统以消息/通知实际时间为参考识别；缺少参考日期时询问具体日期，不直接用导入当天猜测。确认后进入日程和站内提醒。

## 建议推进顺序

1. 校园事项手动录入、通知文字导入预览与统一日程，先形成“录入→看截止→提醒→完成”的可用闭环，不依赖全国高校采集齐全。
2. 选择少量真实学校/部门，接入公开新通知、订阅和加入日程，验证更新、去重与时间变化。
3. 扩展文件/截图辅助识别、日历周视图、冲突提示，再接通助手问答与按需材料自查。上述步骤都属于本批待开发范围，不以第一步代替24条全部完成。

浏览器系统通知、邮件/微信提醒、课程表/ICS导入导出及教务系统集成为后续可讨论增强，暂未列入24条正式验收；不假定本轮已授权外发通知或获取教务账号密码。首批学校、是否需要这些增强及上线通知渠道可在具体开发前集中确认，本轮无需学生先提供学校凭据。

## 与原有需求的关系

CAMP24条为新校园场景，独立于UXR-33—35展示精简12条、PREP48条和EXP/PORT88条，各自按原编号验收。日历、提醒、身份隔离、文件解析和助手复用现有能力，不把共用实现重复统计成独立功能总数，也不将旧测试通过视为本批验收通过。

本轮仅新增需求和索引，不修改应用代码、运行配置或真实用户数据，不采集学校网站、不调用模型、不运行功能测试、不推送部署或关机。原3个配置改动保留。
