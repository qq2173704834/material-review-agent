## 1. 目标与适用范围

目标：用户在一个工作台里看清提交要求、发现材料问题、核对原文证据、处理疑问、修改材料并确认复检变化，最后获得可追溯的报告。

沿用单机本地版、动态通知规则、既定技术方向与五类判定。原始 [114 条需求](requirements.md) 和 AT01—AT12 保留；本文件以 OPT-01—OPT-10 对产品体验和验收进一步细化，不代表新增 10 项已经实现的功能，也不替代原清单中其他未完成需求。

本文件是后续开发依据。具体布局、批次顺序和评估样本规模是本次细化方案；正式品牌名、外观稿、质量测量结果不预设为用户已认可或已获得。当前实现依据 [任务记录](tasks.md)，不能从需求文本推断完成状态。

优先级：一级为核心工作台体验，二级为处理疑问、复检与识别增强，三级为效果评估与交付完善。它们表示本次优化顺序，不重写原清单 P0/P1/P2。

## 3. 详细行为与验收条件

每个编号下的 A1—A4 是可独立追踪的验收条目，例如 OPT-04.A2。只有相关条目实测通过，才能在任务记录里标记该部分完成。

### OPT-01 联动审查工作台

用户目标：查看某个问题时，在同一工作空间找到通知要求、对应材料和整改建议。

行为：桌面端左侧为规则/材料导航，中间为来源或材料预览，右侧为当前检查项。顶部展示任务、当前版本、执行状态、五类判定数量、未执行数量与待复检提示。背景编辑、补充来源管理和历史操作使用独立标签或抽屉。首次进入优先展示必须项未通过的问题，其次为待确认、无法检查；用户选择后不因新的结果到达而自动切走。

- A1：点击任一检查项，三个区域同时关联同一规则和执行快照；显示的引用与材料版本属于该次执行。切换历史执行不能混入当前版本内容。
- A2：按结论、材料、要求强度筛选后，数量和列表一致；明确区分筛选结果数量与整次执行数量。空筛选提供清除筛选入口。
- A3：刷新和浏览器后退恢复当前任务、执行、检查项及筛选；目标失效时回到有效位置并解释原因。界面状态不向地址栏写入材料原文或敏感字段。
- A4：1440×900 和 1280×800 桌面窗口可使用联动布局；390×844 窗口以标签/抽屉提供相同内容，页面不发生整体横向溢出。文档预览自身可以缩放或滚动。

### OPT-02 阶段导航与下一步提示

用户目标：知道目前到哪一步，以及下一步需要做什么。

行为：导航包含导入要求、准备材料、审查、整改复检、导出五个阶段。规则提取、补充来源与背景澄清归入前两个阶段。阶段完成情况由已保存的数据和执行状态推导；执行结束只代表检查完成，不代表材料全部通过。允许回到前面修改并触发已有失效机制。

- A1：没有来源时主要操作为导入要求；有来源但规则未提取或已过期时为生成/更新规则；条件具备后可以发起审查。即使没有材料，也允许检查必交材料缺失，不能统一禁止执行。
- A2：条件未知或单个文件失败只影响关联检查；提示影响范围，允许独立项继续。没有满足前置条件的操作显示具体原因和补救入口。
- A3：上传、解析、规则提取和检查分别显示实际状态；不知道总量时使用不定量状态，不编造完成百分比。取消后保留已完成结果，并明确未执行数量。
- A4：任务中途刷新可恢复已持久化进度；失败提供对应重试或替代输入入口。重试不会重复创建任务或不必要的材料版本；回退编辑未保存内容时有离开提醒。

### OPT-03 材料清单与匹配总览

用户目标：一眼看清本次需要提交哪些材料，以及上传文件是否对应正确。

行为：按通知提取的提交对象形成清单，展示名称、强度、适用条件、数量要求、来源、关联规则、候选文件及当前匹配状态。匹配状态包括未提供、候选待核对、已匹配、不适用；它们与审查判定分开。一份文件可以对应多条规则，同一要求可以关联多份文件。

- A1：对包含必交、选交和条件材料的通知，分别展示三种性质；选交未提供不会显示为必交缺失，条件未知保持待确认。
- A2：候选匹配显示材料内容依据或人工指定标记；文件名相同但内容不相关时，不自动视为可靠匹配。未匹配文件单独可见。
- A3：用户在清单中关联、移除或替换文件，保存后刷新仍可恢复；变更保留记录并使相关旧结果待复检。服务端拒绝其他任务的材料 ID。
- A4：至少覆盖“一文件多规则”和“多文件同一要求”的展示与保存；多文件被关联不等于已满足组合要求。二选一等关系未被明确解释时保留待确认，并链接规则依据。

### OPT-04 原文预览与证据高亮

用户目标：直接核查结论使用的原文，减少下载和手工查找。

行为：支持要求来源和材料预览。PDF 使用页码定位；DOCX 显示解析段落/表格；TXT/CSV 显示行；XLSX 显示工作表及行；JPG/PNG 显示原图与识别文本。网页来源预览保存的正文版本，提供原始 URL。对比问题可同时打开两份材料和各自证据。

- A1：点击引用在不离开任务的情况下打开正确版本并定位对应页/段落/行，引用文字高亮，上下文可展开；关闭预览返回原问题和筛选位置。
- A2：项目名称不一致的案例中并排显示两份文件、版本、位置和原文；用户无需自行切换文件寻找两处字段。
- A3：只有文本偏移而没有图像坐标时，只高亮解析文本；有真实坐标后才在原图/PDF 上画框。DOCX 解析预览不标为原始排版，无法定位时给出明确原因和文本回退。
- A4：历史执行打开当时版本；若原件确实不可用，保留已保存证据并说明情况。预览服务验证任务与文件关联，不接受任意磁盘路径；长文档按页或片段加载，不一次返回整份内容。

### OPT-05 检查依据与覆盖范围

用户目标：知道结论靠什么得到，以及哪些内容还没有核验。

行为：结果卡片包含要求、判定、原因、检查方法、来源证据、材料证据、覆盖限制、建议和版本。程序核验、模型辅助、组合检查使用明确标签；人工意见独立展示。OCR 是文字提取方式，不包装成独立的合规判断。硬性问题与可选质量建议分别展示。

- A1：同屏可区分程序核验结果和模型辅助结果；人工认为符合不会覆盖原系统判定。规则不适用有对应背景依据。
- A2：PDF 总页数案例显示“要求值、实际值、比较方式、工具读取范围”；语义案例显示实际引用和检索覆盖。不能用“有章节标题”代替实质内容判断。
- A3：解析失败页、OCR 低质量区域、未检索部分、取消未执行项可以查看；未知覆盖标为未知。数量统计不把待确认、无法检查或未执行计为通过，不用一个总体分数掩盖它们。
- A4：执行详情显示实际工具事件、模型/模式、耗时和已报告 token；未返回用量显示未知。仅在存在明确价格来源和版本时展示估算费用；不展示编造的内部思考过程。

### OPT-06 疑问处理与整改操作

用户目标：看到待确认或失败项后，能立即采取对应操作。

行为：问题卡片按原因提供补充背景、选择冲突依据、纠正规则、调整匹配、替换材料、记录人工意见或创建整改待办。相同问题合并询问。动作完成后显示影响的规则和结果，并引导复检，不直接修改系统结论。

- A1：团队条件未知时直接打开相关背景问题；用户可以跳过，关联项保持待确认，无关项继续执行。补充后保存背景版本并使受影响结果待复检。
- A2：冲突项同时展示双方原文和来源；用户选择采用依据或保留待确认。选择写入新规则版本，历史规则和结果仍可追溯。
- A3：匹配不确定、解析失败分别进入匹配纠正和重新上传入口；保存失败保留用户已输入内容。人工确认必须填写依据，并显示操作时间和适用执行版本。
- A4：整改项展示问题、要求来源、当前证据、可执行建议和状态；重复创建不产生重复待办。标为已处理后仍需系统复检，不显示为已通过；建议不得杜撰缺失的项目事实。

### OPT-07 修订影响与增量复检

用户目标：修改材料后看清需要重查什么，以及问题是否真的解决。

行为：区分文件版本、解析文本版本、规则/来源版本、匹配关系和背景变化，建立检查依赖。上传修订版后列出受影响项及原因；默认重查受影响项，并提供全量复检。只有依赖和执行配置一致、覆盖足够时才复用旧结果，复用项保留原执行与时间。

- A1：修改一份材料时，直接关联规则及跨材料一致性规则均纳入影响范围；无法证明其他规则不受影响时保守扩大范围，不能漏检后继续显示有效。
- A2：背景、冲突依据、来源、规则、匹配或 OCR 人工文字变化也触发影响分析；模型、提示配置或工具版本变更后，不能未经兼容性判断复用旧结论。
- A3：复检详情区分新执行、复用、未执行、失败；复用结果不伪造新检查时间或模型用量。取消或部分失败不把旧结果冒充本轮已完成结果。
- A4：相同问题使用稳定关联展示已解决、仍存在、新增、变化待确认；缺少可比依据时明确不能比较。待确认/无法检查不算已解决，停用规则单独说明，不能冒充整改成功。

### OPT-08 扫描件识别与文字纠正

用户目标：扫描 PDF 和图片中的信息能够参加审查，同时能核对和纠正识别错误。

行为：对扫描 PDF 和混合 PDF 逐页判断可提取内容；需要时执行 OCR，记录页码、提取方式、状态和识别文本。已有 JPG/PNG OCR 纳入同一覆盖展示。提供原图与文字对照、人工修订、恢复原始识别文本，修订形成独立解析版本。来源文件的文字修订同时影响规则有效性。

- A1：用文本 PDF、纯扫描 PDF、混合 PDF 分别验收；混合文件不能因部分页面有文本就标为全文完整。页内同时存在文本和图片且未全面识别时披露覆盖限制，避免重复拼接同一段内容。
- A2：对每页显示读取方式与状态；单页失败可重试且不丢失成功页。文件大小、页数、渲染像素、队列和执行时限设有已记录上限，超限页显示未处理及原因，取消后不继续排入后续页。
- A3：人工修订保存原始文本、修订文本、修订时间和版本；新检查引用修订版本并标记人工修改，旧执行仍定位旧文本。修订失败不能破坏旧解析结果。
- A4：乱码、低质量和漏读风险会影响依赖该内容的检查；OCR 分数不表示合规概率。缺少单元格结构时不能凭 OCR 行文本执行可靠的表格合计核验；手写、签章真伪等未验证能力明确披露。

### OPT-09 演示案例与质量评估

用户目标：首次使用者能体验完整流程，评审者能核查项目效果与限制。

行为：提供至少两种领域的演示材料，建议竞赛提交与项目申报。规则均从各自通知生成。演示故事包含导入要求、材料匹配、发现问题、查看证据、修订复检、报告导出。案例数据使用合成或获准公开内容；演示任务与用户真实任务分开。

- A1：一键创建可重置的独立案例，不覆盖用户任务；样例初始至少包含必交缺失、跨材料字段不一致、只有标题没有实质内容三类问题，并提供修订版。演示模式、实时真实模型结果与历史记录明确标识。
- A2：验收资产覆盖 AT01—AT12，其中包含规则冲突、解析不完整、干扰指令和切换领域。每个场景记录输入、预期行为、实际输出、执行版本及通过/失败/未执行；不能用样例数量代替覆盖说明。
- A3：首轮质量评估方案至少包含 20 组完整任务样本、两个领域、合计 60 条人工标注规则。覆盖成功、失败和不确定样本，保留人工标注依据与争议；固定一部分样本供修改后复测，展示案例与评估样本分别标记。
- A4：报告给出规则提取精确率与召回率、问题检出率、误报情况、证据位置正确率、保留不确定结果的数量、耗时与用量，并提供各指标分子/分母、样本版本和运行条件。样本过少时展示原始计数，不宣称业务总体准确率；质量目标在首轮基线后提出，未测量不填写成绩。

### OPT-10 报告、视觉与无障碍规范

用户目标：能读懂、打印和交付审查结果，使用过程中的状态表达一致。

行为：保留完整 Markdown 报告和独立整改清单，增加报告预览及可打印 PDF 导出。统一工作台、列表、预览和报告中的判定名称、颜色、图标与文案。正式名称尚未决定，继续使用材料预审工作台。

- A1：从任一执行快照导出 Markdown/PDF，均包含任务、时间、来源/规则/材料版本、检查范围、五类判定、未执行项、逐项依据、整改建议、人工意见和能力限制；同一快照跨格式数量与文字结论一致。
- A2：A4 打印下中文、长文件名、长链接、多页证据和表格可读，无裁切或文字重叠；分页显示页码，颜色转灰度后仍能区分状态，文件不含密钥和内部磁盘路径。导出失败提供重试，保留可用的 Markdown 导出。
- A3：整改清单可单独阅读，注明待办与系统结论的区别；复用结果、OCR 人工修订及复检变化保留来源标记。报告没有未核验项且全部适用项有有效通过证据时，才允许使用“全部适用要求已核验通过”。
- A4：主要流程可用键盘完成；焦点可见，抽屉/弹窗关闭后返回触发位置；状态使用文字与图标而非只靠颜色，表单错误关联对应字段。正常文字对比度至少 4.5:1、大文字至少 3:1，移动端主要操作触控区域至少 44×44 CSS 像素。
