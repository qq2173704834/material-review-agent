## 项目概况

考试与学习面向在校大学生，将考试信息、校园通知、个人日程、学习资源、AI咨询和材料自查放在同一个网站中。用户可以从一条考试公告出发，保存自己的备考目标，查看相关资料，管理报名及学习安排，并在提交材料前进行辅助检查。

学生关注的事情通常分散在教育考试网站、学校教务通知、课程要求和个人备忘中。本项目以个人考试目标为关联点，将“发现信息”和“落实准备”连接起来。材料自检是重点功能之一：将通知要求与待提交文件逐项比较，指出缺项、格式、大小及信息一致性问题，支持修订复检和保存结果。

## 主要功能与使用场景

### 考试信息与个人目标

首页展示已收录的近期考试信息、报名与考试状态，以及个人备考入口。考试中心支持类别、地区和关键词筛选，查看公告正文及来源。用户可收藏公告，将对应考试保存为目标，补充考期、学习阶段、每天学习时间等信息。

目标关联已收录公告后，明确的考试节点可以出现在个人日程中。考期未选定、来源未给出日期等情况分别提示；系统不将未知日期补成一个看似确定的安排。

### 日程管理

我的日程区分考试安排、报名与申请、作业与报告、活动与其他。用户可以添加课程考试、作业截止、学习报告等私人事项，在列表和月历间切换，通过弹窗编辑，并标记完成。时间待定事项单独展示，避免混入某一天。

新增和编辑使用统一弹窗。保存成功后关闭编辑器；保存失败时保留输入，用户可重试。日程、目标与收藏数据按账号隔离。

### 校园通知与学习资源

校园通知支持按学校名称查找和保存关注学校；已选学校的设置默认收起，主区域展示已接入公开来源的通知。用户可查看原文、收藏需要的通知，并将适用安排加入自己的日程。学校名称目录和各校通知来源独立维护，页面提供已接入来源与官网入口。

学习资源按考试方向、内容形式与学习阶段组织考纲、课程、资料、练习和资讯。用户可查看来源、收藏资料并记录已看或未看，结合自己的考试目标继续准备。部分内容为官方入口，部分为明确标注的参考资料或AI辅助编辑内容。

### AI考试与学习助手

右下角的原创鲸鱼助手提供考试咨询和学习建议入口。系统可结合所选考试目标、已收录公告和知识内容组织回答。对学习计划类问题提供任务拆解；对报名日期、地区政策等需要依据的问题，优先使用适用来源，信息不足时请求补充或保留不确定性。

真实服务通过兼容接口接入DeepSeek，模型凭据保留在服务端。知识检索将所选目标、已收录公告和相关文本片段整理成问题上下文，辅助组织回答。视频使用演示模式展示资料检索与问答流程。

### 考试材料自查

这是视频第4、5章重点演示的功能。用户在“我的备考”点击“新建材料自查”，提供通知要求、上传文件，启动检查后先查看需修改项与整体结论。

材料自查支持粘贴要求、导入要求文件或关联已有考试公告，上传材料后整理要求并逐项检查。常用材料包括PDF、DOCX、TXT、XLSX、CSV、JPG、PNG；还具备受限的视频、压缩包及公开链接处理能力。材料解析范围不足时保留提示，不将未读取内容当作已检查。

文件格式、大小、数量和明确数值等交由程序工具核对；语义要求由模型结合检索到的材料片段辅助判断。每项结论保留要求出处与材料证据，区分通过、未通过、待确认、无法检查、不适用，执行失败或未完成不会显示为全部通过。

用户上传修订材料或修改要求后，旧记录仍保留，当前结果标记需要重新检查。明确点击重新检查后生成新记录，浏览页面和切换阶段本身不触发真实模型调用。结果页优先展示整体结论、问题与下一步，详细依据按需展开，可导出简版报告和完整检查记录。

视频案例要求TXT格式、文件大小不超过1KB。初始报告超过大小上限，系统指出大小问题并给出要求与材料依据；上传精简后的同名文件后，页面提示重新检查，复检通过两项规格要求，再打开简版报告。该案例串起“要求—材料—问题—修订—复检—结果”的完整操作。

## 项目亮点

1. 以个人目标连接信息与行动。公告收藏、考试目标、日程和资料围绕同一考试衔接，减少重复查找。
2. 将校园事务纳入备考场景。公开校园通知与私人作业、课程考试分别管理，在个人日程中按用户关系组织。
3. 将大模型与明确工具配合。可计算的规格由程序比较，语义判断保留证据与未知状态，避免把所有检查都变成一次无依据的问答。
4. 材料修改后有明确复检流程。保留历史和原件，提示旧结论的适用范围，用户知道何时需要再次检查。
5. 展示优先考虑普通学生。页面保留主要操作，低频设置、历史依据和技术细节按需打开，适配桌面与手机。

## 关键技术与实现方式

Next.js、React与TypeScript用于构建考试信息、日程、学习资源和材料自检页面，兼顾电脑与手机。SQLite数据库保存账号、收藏、日程和检查记录，让每位用户管理自己的数据。

文件解析与OCR文字识别用于读取PDF、Word、表格和图片内容，为材料检查提供文本。DeepSeek大模型结合考试资料回答问题、生成学习建议，并辅助理解通知要求和检查材料内容。

材料自检先整理通知中的提交要求，再读取用户材料逐项比较。格式、大小和数量等明确规则由程序检查；需要理解内容的要求交给AI结合材料判断，并展示对应依据。材料修改后可以重新检查，生成新的结果。

网站使用Docker部署到云服务器，通过HTTPS供浏览器访问，配合定时更新与备份。具体接口、文件解析工具、账号权限和部署配置见随附技术PDF及源码中的环境说明。

## AI测试技术的落地使用

AI功能分三步验证：先用演示数据检查上传、发现问题、修改复检和导出结果的完整操作；再用固定测试回答，检查回答缺失、格式错误和请求失败时系统能否正确处理；最后连接真实DeepSeek接口，用专门编写的测试通知与材料验证学习建议、要求提取和材料内容检查，3次调用均完成。

最近一轮135项自动化单元测试通过，审查流程完成28项受控测试，云端电脑与手机完成38个浏览器检查点；生产构建、代码检查和备份恢复验证通过。不同测试分别保留样例和结果，详细记录随源码提供。

## 快速使用说明

1. 打开网站，注册用户名和密码并妥善保存恢复码，或使用提供的测试账号登录。
2. 在首页或考试中心查找考试，查看公告与来源，收藏或保存为考试目标；选择适用考期。
3. 在我的备考查看目标，在我的日程管理考试节点、作业和其他事项，填写明确的截止日期。
4. 在校园通知选择学校，查看已接入来源的通知；在学习资源按目标查找资料，收藏并记录阅读状态。
5. 点击右下角助手，输入考试或学习问题；涉及政策与个人场次时提供地区、年份等必要背景。
6. 在我的备考选择新建材料自查，提供要求和材料，点击主操作启动检查；查看问题、依据与下一步。
7. 修改材料后重新上传，确认待复检提示，点击重新检查并查看新结果；按需要导出报告。

## 运行与已知范围

本地开发环境为Node.js 24与pnpm 11.25.0。安装锁定依赖后执行pnpm build，再执行pnpm start启动生产服务；初次开发可使用pnpm dev。模型配置参考.env.example，真实密钥仅放本地或服务器环境文件，不包含在提交源码中。Docker运行参考deploy/Dockerfile与部署说明。

系统按来源维护考试与校园信息，支持用户查找信息、整理学习安排和检查待提交材料。材料读取状态、待确认项和重新检查提示随具体操作显示，用户可继续补充信息或查看原件。

视频使用示例账号、材料与中文合成配音，助手和自检镜头使用演示模式。开源框架与依赖信息见源码中的package.json及pnpm-lock.yaml。
